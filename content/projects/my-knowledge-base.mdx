## 为什么这个项目值得看

这个项目用于展示 AI 应用工程不只是调用模型 API：业务后端管理身份、知识库权限、文件和任务，RAG 服务负责解析、检索与生成。2026-09-23 的隔离联调以合成文件验证了真实 Java、FastAPI、PostgreSQL/pgvector 和本地 Ollama 后端链路。

## 值得继续讨论的工程问题

- 为什么把 Java 业务后端和 Python RAG 服务拆开
- 文档从上传到 pgvector 入库经历了哪些阶段
- score threshold、无命中拒答和 Sources 分别解决什么问题
- 如何从早期 Dify 方案演进到本地 RAG，以及当前联调证据覆盖和未覆盖的范围

## 如果继续迭代

- 让浏览器前端连接真实 Java/RAG 服务完成端到端验收，并刷新问答截图
- 在干净机器上复验首次启动、Docker Compose、MinIO 与 OCR 等尚未覆盖的能力
- 扩充检索评测集并重新验证 threshold 泛化，再完成真实浏览器连接后端的端到端验收
