Java 后端面试检查清单 v1.0.0

使用方法
1. 第一轮按模块自查：能否在 2 分钟内说清概念、场景和边界。
2. 第二轮补项目证据：每个重点至少准备一个真实项目例子。
3. 第三轮模拟追问：解释为什么这样设计、失败时如何处理、还有什么替代方案。
4. 不会的项目先标记，不要背结论；回到官方文档或可运行样例补齐证据。

一、Java 基础
[ ] 能解释 equals 与 hashCode 的约定，以及 HashMap 中违反约定的后果。
[ ] 能比较 ArrayList、LinkedList、HashSet、TreeSet 的复杂度和适用场景。
[ ] 能说明 HashMap 的数组、链表、红黑树结构，以及扩容和并发修改风险。
[ ] 能解释泛型擦除、上下界通配符和 PECS 原则。
[ ] 能区分 checked exception 与 unchecked exception，并说明异常边界如何设计。
[ ] 能说明 String、StringBuilder、StringBuffer 的差异和字符串常量池。
[ ] 能解释不可变对象的价值，以及如何设计一个真正不可变的类。
[ ] 能说明反射、注解、代理的基本原理和常见使用位置。
[ ] 能解释 try-with-resources 为什么能可靠释放资源。
[ ] 能结合项目说明 Stream API 的收益、可读性边界和并行流风险。

二、JVM 与性能排查
[ ] 能画出堆、虚拟机栈、方法区、程序计数器的职责。
[ ] 能解释对象创建、逃逸分析、栈上分配和标量替换的关系。
[ ] 能说明类加载的双亲委派，以及什么时候可能需要打破它。
[ ] 能比较 G1、ZGC 等收集器的目标，不只背收集算法名称。
[ ] 能解释 Minor GC、Mixed GC、Full GC 的触发原因和观察指标。
[ ] 能说明强引用、软引用、弱引用、虚引用的差异。
[ ] 能用 jps、jstack、jmap、jcmd 或 Arthas 完成基本定位。
[ ] 遇到 CPU 飙高时，能描述从进程、线程到代码栈的排查顺序。
[ ] 遇到内存持续上涨时，能区分缓存增长、泄漏、流量增长和配置不足。
[ ] 能解释 OOM 常见类型，并说明日志、heap dump 和现场保护策略。

三、并发编程
[ ] 能解释 Java Memory Model、happens-before 和可见性。
[ ] 能说明 volatile 能解决什么、不能解决什么。
[ ] 能比较 synchronized、ReentrantLock、读写锁和 StampedLock。
[ ] 能解释 CAS、ABA、自旋开销和原子类的适用边界。
[ ] 能说明线程池核心参数，以及队列和拒绝策略如何影响系统稳定性。
[ ] 能识别死锁四条件，并用线程转储定位死锁。
[ ] 能解释 ThreadLocal 的使用场景、内存泄漏风险和清理方式。
[ ] 能说明 CompletableFuture 的组合、异常处理和线程池隔离。
[ ] 能比较 ConcurrentHashMap 与 Collections.synchronizedMap。
[ ] 能结合业务说明幂等、乐观锁、悲观锁和分布式锁的选择依据。

四、Spring 与 Spring Boot
[ ] 能解释 IoC、依赖注入和 Bean 生命周期。
[ ] 能说明 JDK 动态代理与 CGLIB 的区别，以及 Spring AOP 的限制。
[ ] 能解释事务传播行为、隔离级别和 rollback 规则。
[ ] 能说明 self-invocation、异常被吞、非 public 方法导致事务失效的原因。
[ ] 能描述一次 HTTP 请求从 Filter、Interceptor 到 Controller 的链路。
[ ] 能说明配置绑定、Profile、条件装配和自动配置原理。
[ ] 能解释 Spring MVC 参数校验、统一异常处理和错误响应设计。
[ ] 能说明认证与授权的区别，以及接口权限校验应放在哪一层。
[ ] 能解释 Bean 循环依赖，不把“三级缓存”当作所有场景的万能答案。
[ ] 能结合项目说明如何做健康检查、优雅停机和配置分层。

五、MySQL 与数据建模
[ ] 能解释 B+Tree 索引、聚簇索引、回表和覆盖索引。
[ ] 能说明最左匹配、索引下推，以及常见索引失效原因。
[ ] 能读懂 EXPLAIN 的 type、key、rows、Extra 等关键字段。
[ ] 能比较 READ COMMITTED 与 REPEATABLE READ，并解释 MVCC。
[ ] 能说明间隙锁、临键锁和死锁产生场景。
[ ] 能描述慢 SQL 的发现、复现、执行计划分析和验证过程。
[ ] 能解释深分页问题，并给出基于游标或覆盖索引的方案。
[ ] 能说明唯一约束、外键、应用层校验各自能保证什么。
[ ] 能设计订单、库存、任务等状态流转，避免非法状态跳转。
[ ] 能结合业务解释分库分表的收益、复杂度和真正触发条件。

六、Redis、消息队列与一致性
[ ] 能说明 Redis 常用数据结构及其真实业务映射。
[ ] 能解释缓存穿透、击穿、雪崩，并给出有边界的治理方案。
[ ] 能比较 Cache Aside、Read/Write Through 等缓存模式。
[ ] 能说明数据库与缓存双写不一致的窗口和补偿方式。
[ ] 能解释分布式锁的超时、续期、误删、主从切换风险。
[ ] 能说明消息至少一次投递下，消费端为什么必须幂等。
[ ] 能描述消息重复、乱序、积压、丢失的发现和处理方式。
[ ] 能比较本地事务表、Outbox、事务消息和最终一致性方案。
[ ] 能说明重试为什么需要退避、上限、死信和人工兜底。
[ ] 能结合流量和一致性要求判断是否真的需要 Redis 或 MQ。

七、网络、Linux 与运维
[ ] 能说明 TCP 三次握手、四次挥手和 TIME_WAIT。
[ ] 能解释 HTTP 缓存、Cookie、Session、CORS 和常见状态码。
[ ] 能说明 HTTPS/TLS 解决了什么，以及证书校验的基本过程。
[ ] 能解释 Nginx 反向代理、负载均衡、超时和请求头转发。
[ ] 能用 ss、lsof、curl、top、free、df、journalctl 完成基础排障。
[ ] 能区分进程存活、端口监听、健康检查通过和业务真正可用。
[ ] 能说明日志中 traceId、结构化字段和敏感信息脱敏的重要性。
[ ] 能说明 CPU、内存、磁盘、连接池、线程池的基础监控指标。
[ ] 能描述发布前检查、灰度、回滚和发布后观察窗口。
[ ] 能解释容器的镜像、卷、网络、资源限制和健康检查。

八、系统设计答题框架
[ ] 先确认用户规模、读写比例、延迟、可用性和一致性目标。
[ ] 明确核心用例、非目标和失败边界，不急着画复杂架构。
[ ] 给出 API、数据模型、状态流转和幂等键设计。
[ ] 估算容量、峰值 QPS、存储增长和带宽，不只给组件名称。
[ ] 说明缓存、队列、分片、复制分别解决什么问题。
[ ] 说明超时、重试、限流、熔断、降级和补偿策略。
[ ] 说明可观测性：日志、指标、追踪、告警和审计。
[ ] 主动指出单点、热点、数据丢失和一致性风险。
[ ] 给出从简单方案演进到复杂方案的触发条件。
[ ] 最后回到业务目标，说明成本、收益和团队维护能力。

九、项目表达检查
[ ] 30 秒说清项目背景、目标用户和你的职责。
[ ] 说明一个由你主导的关键技术决策及其替代方案。
[ ] 用真实数据、测试结果、日志或提交记录支撑成果。
[ ] 说明遇到的故障或失败，而不是只讲最终成功状态。
[ ] 说清安全、性能、一致性和运维边界，没有证据就明确保留。
[ ] 能从一次请求或任务开始，串起入口、业务层、数据层和异步链路。
[ ] 能说明项目当前不足，以及下一步最值得做的改进。
[ ] 确保简历数字、仓库代码和现场回答口径一致。

十、面试前 24 小时
[ ] 核对简历、项目链接、演示地址和 GitHub 是否可访问。
[ ] 准备 2 个主项目、1 个故障案例、1 个协作案例。
[ ] 复查岗位描述中的高频关键词，不临时扩展大范围新知识。
[ ] 检查摄像头、麦克风、网络、IDE 和共享屏幕权限。
[ ] 准备纸笔，记录问题和不会的点，面试后及时复盘。
[ ] 保证睡眠和到场时间，不用熬夜换取短期记忆。

完成标准
- 不是“看过”，而是能用自己的话回答并承受两轮追问。
- 不是“做过”，而是能指向代码、数据、日志或决策记录。
- 不确定的内容明确说边界，不用猜测包装成确定结论。
